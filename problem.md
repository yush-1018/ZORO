Implement a task-level circuit breaker for Celery that tracks task failures within a sliding time window. Tasks opt in by setting circuit_breaker = True on the task class, configured with circuit_breaker_threshold, circuit_breaker_recovery_timeout, circuit_breaker_half_open_max_calls, circuit_breaker_failure_window, and circuit_breaker_exclude, falling back to global app settings task_circuit_breaker_threshold, task_circuit_breaker_recovery_timeout, task_circuit_breaker_half_open_max_calls, task_circuit_breaker_failure_window, and task_circuit_breaker_exclude.

The module celery.utils.circuitbreaker exports CircuitBreaker with constructor parameters task_name, threshold, recovery_timeout, half_open_max_calls, failure_window, exclude, and clock. The class provides state property, can_execute(), record_failure(exc=None), record_success(), reset(), and stats() returning state, failure_count, threshold, recovery_timeout, failure_window, half_open_max_calls, and opened_at. CircuitBreakerRegistry provides get_or_create(task_name, ...), get(task_name), all_stats(), reset(task_name), and clear(), stored on the Celery app instance as app._circuit_breaker_registry.

When the threshold is reached, state becomes open, refusing execution with CircuitBreakerError having task_name attribute and string representation "Circuit breaker open for task {task_name}". After recovery_timeout seconds, state becomes half_open allowing probe calls up to half_open_max_calls. Probes that succeed close the circuit; failed probes reopen it. Lifecycle signals in celery.signals are circuit_breaker_opened with task_name and failure_count, circuit_breaker_closed with task_name, and circuit_breaker_half_opened with task_name. Worker control commands include celery.worker.control.circuit_breaker_stats, and celery.worker.control.circuit_breaker_reset returning {"ok": "circuit breaker reset for {task_name}"} or {"error": "no circuit breaker for {task_name}"}.
